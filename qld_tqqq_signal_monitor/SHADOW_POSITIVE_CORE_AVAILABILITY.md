# Positive-core target verification when VIX statistics are unavailable

PR18's second live test recovered the current October 30 BASE bundle, then failed because Cboe had not yet supplied that session's VIX close and FRED timed out. The verified core score was 1. The frozen rule permits a VIX overlay ONLY at exactly zero core, so every possible valid VIX amplitude gives exactly the existing BASE weights at positive core.

The shadow module still attempts normal VIX acquisition and verification. If VIX coverage is unavailable and the independently revalidated core score is positive, it produces core-determined targets and sets `comparison_basis=positive_core_overlay_disabled`, `vix_data_status=unavailable_not_required_for_positive_core`. VIX features/source/hash are null, provider errors remain recorded, no vix_used.csv is emitted, and the human report explicitly states that VIX statistics were not verified. This is target verification, not evidence that the VIX provider is current.

At zero core missing VIX still fails with no models, preserving the source error. Invalid core/schema/date/volatility, source-independent program errors, altered BASE files and stale bundles still fail. When real VIX data becomes available the original complete-data path and mathematics are unchanged. No amplitude is imputed, no new fallback price source is introduced, no production target or publication rule changes, and shadow still never authorizes orders.

All 396 original tests retained. Local suite after the complete PR18 changes: 463 passed, including 42 close/cache cases and 25 positive-core availability cases. The current verified BASE bundle was replayed with VIX explicitly unavailable and yielded QLD 100%, TQQQ 87.25805299567266%, equal across BASE/C20/Q70; all VIX statistics remained null. Tests prove equality for every core regime and amplitude endpoints, and reject zero-core missing data and corrupt inputs. Live workflow verification remains a separate requirement.

# QLD / TQQQ 自动信号通知

该程序在每个美国股市工作日收盘后检查已冻结的趋势与波动率策略，并把结果发布到仓库 issue #1。**每日运行不等于每日调仓。** 程序只生成通知，不连接券商，也不自动下单。

## 固定策略

- 趋势输入：QQQ 价格收盘序列。对当前实盘时期，QQQ 与回测连续信号序列仅相差固定比例，因此均线状态一致。
- 三组趋势参数：50/200、55/220、60/240。
- 每组中 SMA 或 EMA 任一快线高于慢线，该子模型即开启。
- 趋势分数：开启子模型数除以 3。
- 风险输入：NASDAQ-100 最近 21 个交易日的年化已实现波动率。
- 目标波动率：60%。
- QLD 权重：`score × min(2, 0.60 / vol) / 2`。
- TQQQ 权重：`score × min(3, 0.60 / vol) / 3`。
- 剩余仓位：短期美国国债或现金。
- 仅在每月最后一个交易日收盘后生成新目标。
- 新目标在下一交易日开盘执行。
- 其他交易日不调仓，只报告监控状态并继续执行最近一次月末目标。

QLD 和 TQQQ 是两种替代实施方案，不能把两行权重同时叠加。

## 暴跌日与执行边界

该回测策略没有盘中止损、单日跌幅阈值、VIX 应急开关或非月末调仓规则。

- 非月末发生大跌时，程序仍会在收盘后更新趋势与波动率监控值，但不会产生交易指令。
- 月末发生大跌时，程序使用月末收盘数据生成新目标，并在下一交易日开盘执行。
- 任何依赖当日收盘价的信号都不能在同一交易日收盘前执行。
- 增加“暴跌后立即减仓”会形成另一套策略，必须重新进行 1985–2026、QLD 实际期和 TQQQ 实际期回测，不能沿用当前绩效结果。

## 月末通知如何执行

模型在月末给出目标权重。账户内的 QLD/TQQQ 与防御资产会在月内自然漂移，因此“上期月末目标”不是月末当天的实际账户权重。

精确执行方式是：

1. 读取月末通知中的“本期目标”。
2. 在下一交易日开盘，以实际账户持仓为起点再平衡到该目标。
3. 非月末不做重新平衡。

系统不读取券商账户，因此不会把两个目标权重之差误写成实际买卖数量。具体买入或卖出方向取决于账户当时的真实权重。

## 数据与安全控制

- QQQ：Yahoo Finance chart endpoint 的价格收盘字段。程序不使用含现金分配调整的 `adjclose`。
- NASDAQ-100：FRED `NASDAQ100` 日收盘序列。
- 两个数据源都必须包含报告日，并通过长度、重复日期、正价格和最近 60 日收益相关性检查。
- 数据缺失、过期、格式变化或交叉校验失败时，程序拒绝产生交易指令，并在 issue 中报告错误。
- Python 直接依赖锁定到完成端到端验证的版本；GitHub Actions 也固定到已发布 commit。

## 自动运行

GitHub Actions 在每周一至周五 22:30、`America/Los_Angeles` 时区运行。休市日会报告无操作。工作流同时支持手动指定报告日期。

## 本地运行

```bash
python -m pip install -r qld_tqqq_signal_monitor/requirements.txt
python qld_tqqq_signal_monitor/exact_monitor.py
```

指定历史报告日：

```bash
python qld_tqqq_signal_monitor/exact_monitor.py --report-date 2026-08-28
```

输出写入 `signal_output/report.md` 与 `signal_output/signal.json`。
